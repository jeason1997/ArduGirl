# PY32F002A 平台

首次实现中发生的架构、构建和硬件验证错误，以及后续平台必须执行的检查项，见 [PY32 移植错误复盘](PY32_PORTING_RETROSPECTIVE.md)。

## 当前范围

首版目标是 PY32F002A、32 KB Flash、4 KB RAM，使用 Arduventure 验证源码级移植。当前性能配置沿用同一块样机参考工程公开的隐藏 PLL 路径：24 MHz HSI 通过固定二倍频 PLL 得到 48 MHz SYSCLK，Flash 使用一个等待周期；不额外调整 HSI trim。该配置需要在不同芯片批次和工作电压下重新做长时间稳定性验证。SPI 二分频后为 24 MHz；128×64 RGB565 刷新每帧传输 16384 字节，60 FPS 的纯像素带宽约为 0.98 MB/s，低于 SPI 的 3 MB/s 线速。

当前固件使用 ST7789 240×240 RGB565 屏幕。核心 framebuffer 仍是 128×64、1 bit、1024 字节页面布局；显示后端只更新屏幕中央 `(56, 88)` 到 `(183, 151)` 的区域，不缩放。`platform/py32/include/board.hpp` 中的 `ARDUGIRL_COLOR_BLACK_RGB565` 与 `ARDUGIRL_COLOR_WHITE_RGB565` 分别配置 framebuffer 的 0 bit 和 1 bit 显示颜色；启动时外围区域使用 0 bit 的背景色清屏。动态画面按 128 像素扫描线转换到 256 字节缓冲区，再由 DMA1 Channel 1 以 16 位数据帧发送到 SPI1；后端还会对 framebuffer 计算固定宽度哈希，画面未变化时跳过重复的 16 KB RGB565 传输，并至少每 60 次提交强制刷新一次。该设计不增加 1 KB 影子 framebuffer，并避免静态画面拖慢游戏的逻辑帧率。

## 显示切换边界

`platform/py32/include/display.hpp` 是 PY32 平台与具体屏幕之间的唯一渲染边界，只包含初始化和提交 Arduboy framebuffer 两个操作。ST7789 实现在 `src/display_st7789.cpp`。后续切换 SSD1306 或其他屏幕时，应新增同一接口的实现并在构建目标中选择一个驱动，不得修改核心 framebuffer、游戏或公共平台接口。

## 默认引脚

ST7789 引脚沿用参考工程：PA5 为 SPI1 SCK，PA7 为 SPI1 MOSI，PA2 为复位，PA3 为数据/命令。按钮和蜂鸣器集中定义在 `platform/py32/include/board.hpp`：

| 功能 | 默认引脚 |
|---|---|
| LEFT / RIGHT / UP / DOWN | PB0 / PB1 / PB5 / PB3 |
| A / B | PB4 / PB6 |
| 无源蜂鸣器 | PA0 / PA1（跨接） |

按钮使用内部上拉并按低电平有效。更换 PCB 时只修改板级配置，不要把引脚判断带入游戏或兼容层。

当前样机没有连接实体按键，`board.hpp` 的 `ARDUGIRL_BUTTONS_CONNECTED` 默认为 `0`，平台仍为引脚配置内部上拉，但运行时固定报告六键全部松开，避免悬空输入产生虚假按键。接入上述低电平有效按键后将其改为 `1`。

## 音频与存储限制

蜂鸣器跨接 PA0 与 PA1；两脚分别使用 TIM1_CH3 与 TIM1_CH4，以 187.5 kHz 同步 PWM 输出相反占空比，扩大压电片两端的电压摆幅。50 kHz SysTick 只负责生成新的 8 位有符号混合采样，不再直接输出低过采样率的 1 bit 脉冲密度流。PY32 后端独立维护 ArduboyPlaytune 的两个方波声道，并同时合成 ATMlib 的四个声部；ATMlib 波形按上游 AVR 实现映射为 25% 脉冲、方波、三角波和 LFSR 噪声，四声部固定保留一位混音余量以避免硬削波。PCM 波表暂未在蜂鸣器后端实现。

首版 EEPROM 读取返回擦除态 `0xFF`，写入明确返回失败，不会误写程序 Flash。因此可以启动和游玩，但存档不会跨复位保留；实现独立 Flash 页日志式存储后才可把持久化标为完成。

## 构建和烧录

芯片底层依赖固定在 `platform/py32/vendor/`，包含 CMSIS、PY32 设备头、所需 LL、系统初始化、启动汇编、链接脚本和 OpenOCD 配置；构建不再读取参考工程目录，也不依赖游戏生态的 `third_party/`。Windows 下可通过 `TOOLCHAIN_DIR` 覆盖 Arm GNU 工具链位置。根构建入口使用通用游戏参数：

```text
make PLATFORM=py32 GAME=arduventure
make PLATFORM=py32 GAME=arduventure flash
make PLATFORM=py32 test
```

输出位于 `build/py32/arduventure/`。烧录目标使用 CMSIS-DAP 与仓库内固定的 `py32f002a_32k.cfg`，执行写入、校验和复位。

根 Makefile 只按 `PLATFORM` 选择 `platform/<platform>/Makefile`，并原样转发目标和 `GAME` 等命令行变量；构建、测试、烧录及平台工具均由平台目录自行实现。`make PLATFORM=py32 test` 会从全部 `game.toml` 自动发现当前游戏，逐个清理对应的 `build/py32/<game-id>/` 后执行独立冷构建。测试不会在首个失败处停止，结束时统一报告通过数量和失败游戏，便于一次发现整个游戏集合的交叉编译问题。

`tools/prepare_game.py` 通用读取已有 `game.toml` 的游戏编号、上游入口和补丁列表，生成平台无关的可编译源码快照。PY32 构建只接收这份统一输出，不需要每个“平台×游戏”组合的适配文件，也不要求修改游戏目录。芯片、工具链、显示、链接和烧录规则统一归 `platform/py32/` 所有。

源码准备器递归复制 sketch 目录并输出统一入口及同目录 C/C++ 源文件清单，保持 Arduino 构建器的共同编译语义。集合共有的源码差异由各游戏清单显式引用集合目录的声明式 `profile.toml`；因此 Linux、PY32、后续 STM32 和其他后端不需要重复识别 ArduboyWorks 等上游私有宏。

PY32 的 C++ 编译统一启用 `-fsigned-char`，保持 AVR 工具链中普通 `char` 的有符号语义。该设置属于源码兼容编译契约，可避免依赖负数 `char` 数据或判断的游戏在 ARM 上编译失败或静默改变行为，不是针对某款游戏的特判。

MCU 固件链接公共兼容层的轻量 `sprintf` 整数子集，支持字符、字符串、有符号十进制、无符号十进制、十六进制、字段宽度和零填充。该实现不使用动态分配，避免 Arduboy 游戏的一次整数格式化把完整 newlib、浮点格式化、locale 和系统调用桩带入小容量芯片；浮点格式化不属于当前兼容范围。

## 当前验证证据

2026-08-07 启用 48 MHz 隐藏 PLL、16 位 SPI DMA、静态帧跳过和 Sprites 页面对齐快速路径后，Arduventure 完成烧录与校验；复位运行 5 秒读取到 `g_ardugirl_frames=303`、`globalCounter=254`、音频 SysTick 计数约 105858，确认逻辑帧率约为 60 FPS，开场文字已按预期进入标题画面。仍需补充长时间运行和动态玩法画面的稳定性证据。

2026-08-06 的额定 24 MHz 构建与硬件证据保留为历史基线；当前已切换到上述 48 MHz 样机性能配置，仍需执行长时间静置、实测帧率和不同供电条件下的稳定性验收。

2026-08-06 修正 GPIO 单引脚配置后的固件尺寸为 text 28652 字节、data 52 字节、bss 2588 字节。OpenOCD 已识别 Cortex-M0+、写入并完成校验。复位运行三秒后，`g_ardugirl_frames` 为 58，MSP 为 `0x20000f80`；GPIOA MODER 为 `0xEBFFBB5F`，其中 PA2/PA3 是输出、PA5/PA7 是复用功能，SPI1 CR1 为 `0xC347`，确认 SPI1 已按主机、模式 3、单线发送和使能状态运行。

同日使用通用入口构建并烧录 Sunfire：text 17376 字节、data 368 字节、bss 2832 字节；OpenOCD 完成全片写入、校验和复位。
