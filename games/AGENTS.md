# 游戏目录 Agent Guide

本文件适用于 `games/`。全仓规则见根 `AGENTS.md`，导入流程和字段说明以 `docs/GAME_PORTING.md` 为准。

## 上游与目录

- 只有能够取得完整、可编译源码的游戏才进入源码级移植；仅有 `.hex` 或 `.arduboy` 包不在范围内。
- 每款游戏必须有 `game.toml`，记录上游 URL、固定 commit、依赖、补丁和兼容状态。普通游戏不得新增 `port.mk`、手写运行入口或平台专用构建文件。
- 上游源码通过固定 revision 的子模块或可验证快照引入，默认不直接修改。
- 只有兼容层不能表达的真实差异才允许使用最小补丁。补丁位于该游戏的 `patches/`，命名为 `0001-<作用域>-<说明>.patch`，并在 `game.toml` 记录原因。
- 修改上游只能通过 `game.toml` 显式列出的统一 diff；不得增加 sed、正则替换或静默可选替换。
- 多游戏集合由各游戏清单自动发现。确有共享源码布局差异时，可显式引用集合级 `profile.toml`；profile 不得包含平台、工具链或最终目标规则。

## 兼容实现

- 通用 Arduboy/Arduino API 实现在 `src/arduboy2/`、`src/compat/` 或公共接口中，不在单个游戏复制兼容桩。
- 上游私有类型只能留在该上游的适配范围，不得进入核心、公共头文件、根构建文件或其他游戏。
- 生成阶段必须保持上游目录 clean，处理换行差异，并以原子临时文件保证补丁失败不留下有效外观的半成品。多个补丁按编号顺序应用。

## 导入与验收

- 默认一次导入一个游戏。同一固定 revision 的多游戏仓库可以批量接入，但每款游戏仍需独立元数据、构建、冒烟、回放和截图证据。
- 构建验证包含从空产物开始的冷构建；不得用旧生成物或代表样本代替集合结果。
- “可编译”要求独立冷构建通过；“可运行”还要求该游戏冒烟；“完成移植”还要求固定输入回放、玩法验证和截图验收。
- 截图统一保存在该游戏的 `assets/`，必须由当前 ArduGirl 前端实际运行生成，不得使用上游宣传图或其他模拟器图片。
- 完成截图验收至少需要 3 张内容不同且可辨认的画面，并全部嵌入该游戏 README：至少 1 张实际玩法，另外至少 2 张来自标题、菜单、关卡、战斗、关键机制、胜负或存档等不同状态。
- 能构建但缺少运行、回放、玩法或上述截图证据时，状态不得标为 `done`。

## 上游更新

- 移动 revision 必须由用户明确要求，并作为独立任务记录旧/新完整 SHA。
- 更新前先验证无补丁构建，再验证已有补丁；更新后检查源码、依赖、子模块 clean 状态、构建、测试和兼容审计。
- 同步更新 `game.toml`、`docs/UPSTREAMS.md`、游戏 README 和 `docs/PROGRESS.md`。
